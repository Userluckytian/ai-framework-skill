# 代码审查规范

## 代码审查要点（按规模门控分级）

在每次代码提交之前，先按 `AGENTS.md` 的**规模门控**判定档位，再决定审查范围：

| 档位 | 审查要求 |
|------|----------|
| **S 小改** | 仅 diff 目检：一眼确认无逻辑错误、无密钥进入、格式符合规范；不跑全量检查 |
| **M 中改** | 仅审查本次 git diff 涉及的文件（避免全量扫描）；针对性运行受影响模块的测试 |
| **L 大改** | 全量审查 + 全量测试（见 `docs/ai-framework/phased-plan-driven.md` 的四件套） |

审查时关注以下方面：

### 1. 逻辑错误和不正确的行为
- 检查业务逻辑是否正确实现
- 验证条件判断、循环逻辑的正确性
- 注意边界情况的处理

### 2. 边界情况处理
- null/undefined 值的处理
- 空数组、空对象等边界情况
- 极端输入值的合法性

### 3. 资源管理
- 文件句柄、网络连接、数据库连接等资源的释放
- 防止资源泄漏

### 4. 安全性
- 避免 SQL 注入、XSS 攻击
- 敏感信息（密码、密钥等）的处理
- 权限验证的完整性

### 5. 性能考虑
- 缓存在的使用和失效
- 数据库查询的优化
- 重复计算的避免

### 6. 代码风格
- 遵循项目现有代码规范
- 命名一致性
- 注释的必要性

## 提交前检查清单（按档位勾选）

- [ ] 该档位要求的逻辑测试通过（S 级目检 / M 级针对性 / L 级全量）
- [ ] 无敏感信息暴露
- [ ] 资源正确释放
- [ ] 符合提交规范
- [ ] 代码经过审查（S 级为目检，M/L 级为 diff/全量审查）
